# M02 standardized profile PDF

## Purpose / user value

Give a candidate a consistent, downloadable profile artifact that can be
shared outside the platform without exposing protected account data. The
artifact is generated from the current candidate-owned professional profile,
not from the private resume file.

## Requirement IDs

- CAND-003 — generate standardized PDF profile.
- CAND-001 — reuse the candidate profile's professional fields.
- CAND-012 — keep profile artifacts candidate-scoped.
- LEGAL-001 — minimize the exported data and exclude protected fields.

## Current behavior

Candidates can edit and read their private professional profile, but there is
no PDF artifact or download action. The profile API deliberately excludes
email, DOB, minor state, consent metadata, assessment data and resume storage
details.

## Proposed design

Add a deterministic standard-library PDF renderer for a single-column FSP
profile artifact with bounded wrapping and page breaks. It uses only the
profile response fields, includes a clear declared-profile disclaimer, and
returns a fixed safe download filename. A candidate-only GET endpoint streams
the generated bytes; no PDF is persisted and no protected data is queried.
The profile UI exposes the same action and handles loading/error states.

## Files/modules

- `backend/app/profile_pdf.py` — bounded PDF rendering.
- `backend/app/main.py` — candidate-scoped PDF endpoint.
- `backend/tests/test_candidate_profile.py` — artifact, content and role/scope tests.
- `frontend/src/components/candidate-profile.tsx` — download action.
- `frontend/src/app/globals.css` — responsive action styling.
- `docs/PROFILE_PDF.md` — artifact contract and privacy boundary.
- `docs/REQUIREMENTS_MATRIX.md`, `.agent/BACKLOG.md` — IMPLEMENTED evidence.

## Data/API changes

- `GET /api/v1/candidate/profile/pdf` returns `application/pdf` with
  `Content-Disposition: attachment; filename="fsp-standardized-profile.pdf"`.
- The response is generated from display name, headline, location, summary,
  skills, experience and work preferences only.

## Security/privacy implications

The endpoint uses the existing candidate role dependency and the current
principal's self-scoped profile lookup. It does not expose email, date of
birth/minor state, consent versions, assessment/grade, resume bytes or storage
metadata. User text is hex-encoded in the PDF content stream, so it cannot
inject PDF operators. The artifact is not stored server-side.

## Test plan

- generated response is a valid PDF attachment with expected professional
  content and no protected account fields;
- empty profile still produces a readable standardized artifact;
- employer and another candidate cannot read the first candidate's profile;
- frontend typecheck/build and focused backend profile tests.

## Demo/evidence

Candidate profile panel includes a responsive “download standardized profile”
action. Evidence is recorded as IMPLEMENTED in CAND-003; external supervisor
owns VERIFIED.
